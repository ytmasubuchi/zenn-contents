# oldlibs image pins (python:3.10-slim). numpy==1.21.6 is required, not a
# newer 1.x: NumPy's documented stream-breaking changes land at 1.19.0 and
# 1.22.0 (NEP 19). Pinning anywhere at or above 1.22.0 (e.g. 1.26.x) would
# not cross either boundary and the NEP 19 condition this image exists to
# demonstrate would measure nothing (Task 12 resolution 2). numpy 1.21.6
# only ships wheels up to Python 3.10, which is why this image (and oldpy,
# its Python-only counterpart) is pinned to python:3.10-slim rather than
# base's 3.11.
#
# This image's library-version condition is measured on numpy and
# scikit-learn (S1-S6), not torch -- see Dockerfile.oldlibs for why torch
# is absent, and fix-round-1 confirmation below.
#
# scikit-learn==1.0.2 is the version named in the brief; scipy==1.7.3 is
# pinned explicitly even though the brief's prose only names numpy/
# scikit-learn/torch, because scikit-learn 1.0.2 depends on scipy at
# runtime (scipy.sparse, scipy.linalg) and leaving it unpinned would let
# pip resolve to whatever scipy happens to be newest at build time --
# exactly the kind of unpinned dependency resolution 6 forbids. 1.7.3 is
# contemporaneous with scikit-learn 1.0.2 and has a cp310 wheel (verified).
#
# lightgbm==4.5.0 -- the same pin used in base/py313/oldpy -- carries S6.
# Confirmed (fix round 1) that it installs and actually runs (not just
# imports) against numpy==1.21.6/python 3.10 on both linux/aarch64 and
# linux/amd64 (emulated): a LogisticRegression fit/predict and a full
# lgb.train()/predict() round-trip both produced real, non-degenerate
# output on both architectures. Unlike torch, neither scikit-learn nor
# lightgbm showed any numpy-C-API version friction.
#
# torch is deliberately NOT included in this image: see Dockerfile.oldlibs
# for the full writeup, including the fix-round-1 correction of an
# earlier, architecture-confounded version of this finding.
numpy==1.21.6
scipy==1.7.3
scikit-learn==1.0.2
lightgbm==4.5.0
threadpoolctl==3.5.0
